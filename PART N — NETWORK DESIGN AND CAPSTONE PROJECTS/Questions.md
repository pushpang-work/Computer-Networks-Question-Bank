# PART N — NETWORK DESIGN AND CAPSTONE PROJECTS

### Design and analysis questions
264. Design a network for a 50-person office with administration, engineering, guest Wi-Fi, printers, and a server room.
265. Design a campus network with separate VLANs for students, staff, laboratories, and management.
266. Plan IPv4 and IPv6 addressing for a growing organization with multiple sites.
267. Propose routing, redundancy, and failover for a two-site business.
268. Design a secure public-facing web service with a reverse proxy, application server, private database, monitoring, and backups.
269. Create a network security policy covering access, segmentation, remote access, logging, patching, and incident response.
270. Prepare a capacity plan for an organization expecting to double its users in three years.
271. Compare two proposed designs using cost, resilience, security, complexity, and maintainability.

### Capstone projects — complete at least two
272. Small enterprise network: Build multiple VLANs, inter-VLAN routing, DHCP, DNS, ACLs, and a documented addressing plan in a simulator.
273. Linux production-style lab: Deploy a Linux web server and SSH administration, configure a firewall, logs, TLS for a test domain/local service, and backups.
274. Network monitoring toolkit: Build a Python-based tool that records authorized host reachability, latency, DNS health, and service availability.
275. Protocol investigation report: Capture and explain a DNS lookup, TCP handshake, TLS handshake metadata, and HTTP exchange in a lab.
276. Secure segmented network: Separate public services, internal systems, and guest devices; demonstrate allowed and denied paths with test evidence.
277. Containerized application network: Deploy a frontend and backend with a private internal network, reverse proxy, and explicit port exposure.
278. Network automation project: Collect interface and routing data from multiple lab hosts, validate it, and produce a report.
279. Performance troubleshooting case study: Create a controlled lab fault, collect evidence, identify root cause, implement a fix, and retest.
