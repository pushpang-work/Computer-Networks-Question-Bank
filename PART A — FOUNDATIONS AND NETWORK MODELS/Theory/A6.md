## Question 

Differentiate circuit switching, message switching, and packet switching.

## Answer 

The core differences lie in how data is transmitted, whether a dedicated path is used, and how intermediate nodes handle the traffic. 

### Quick Comparison Table

| Feature | Circuit Switching | Message Switching | Packet Switching |
|---|---|---|---|
| Path Setup | Dedicated physical path established before transfer | No dedicated path; hop-by-hop route | No dedicated path; dynamic routing per packet |
| Data Unit | Continuous stream | Entire message as a single unit | Small fragments called packets with headers |
| Storage at Nodes | Not stored (real-time flow) | Store-and-forward at each node | Store-and-forward per packet |
| Bandwidth Use | Inefficient (reserved even when idle) | Efficient channel sharing | Highly efficient (shared dynamically) |
| Latency / Delay | Low and constant after setup | High queuing delay | Low to moderate (may arrive out of order) |
| Main Example | Traditional landline telephone networks | Telegrams, email systems | Modern internet and web data |

### Detailed Breakdown

* Circuit Switching
    * How it works: It requires three distinct phases: connection establishment, data transfer, and connection teardown. A physical or virtual circuit is locked in for the entire conversation.
   * Pros: Guaranteed bandwidth, zero congestion/queuing delay once connected, and predictable performance.
   * Cons: Wastes channel capacity during silent or idle periods, and setup takes time. 
* Message Switching
    * How it works: The entire message is treated as a single block of data and sent from source to destination using a store-and-forward mechanism. Each intermediate switch receives the full message, stores it temporarily, and forwards it to the next node when the line is free.
   * Pros: Does not require a pre-established path, making line sharing flexible.
   * Cons: Introduces massive storage requirements at intermediate nodes and significant queuing delays, making it poor for real-time talk. 
* Packet Switching
    * How it works: Large messages are chopped into smaller pieces called packets, each containing a header with source and destination addresses. These packets travel independently across the network (via datagrams or virtual circuits) and get reassembled in the correct order at the destination.
   * Pros: Extremely high bandwidth efficiency, fault tolerance (if a node fails, packets reroute), and scalability.
   * Cons: Packets can arrive out of order or get lost, requiring extra protocol overhead for reassembly and error checking.
