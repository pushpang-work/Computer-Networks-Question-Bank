# Final Practical Assessment — Integrated Scenario
Scenario: A small organization has 3 departments, 35 employees, guest Wi-Fi, a Linux-hosted internal web application, and remote administrators. Build and document a safe lab representation of this environment.

280. Create a physical/logical topology diagram and list assumptions.
281. Allocate IPv4 subnets using VLSM and document network, prefix, gateway, usable range, and broadcast.
282. Create VLANs for each department, servers, management, and guests.
283. Configure routing and ensure only intended inter-VLAN communication is allowed.
284. Configure DHCP and DNS for the lab where feasible.
285. Deploy a Linux web server and enable only required inbound services.
286. Configure SSH key-based administration and document the access policy.
287. Capture and explain a DNS query, TCP handshake, and application request.
288. Test permitted and blocked communication paths and record results.
289. Add a monitoring script or dashboard for reachability and service checks.
290. Simulate one failure (DNS, route, gateway, or service) and produce a troubleshooting report.
291. Submit a final report with diagram, address plan, configurations, test matrix, screenshots, risks, and improvement plan.

### Practical Report Template
1. Experiment title: Write the task name and experiment number.
2. Objective: State what you intend to configure, measure, or verify.
3. Environment: List OS, tools, versions, topology, and relevant IP addresses.
4. Theory: Summarize the networking concept in your own words.
5. Procedure: List commands and configuration steps in order. Remove secrets before submission.
6. Evidence: Add screenshots, output snippets, packet-capture observations, or diagrams.
7. Results: Compare expected and actual behavior.
8. Troubleshooting: Record errors, hypotheses, tests, and the confirmed cause.
9. Conclusion: State what was learned and any limitations.
